# 안심 주행 코칭 & 내비게이션 서비스 기획서

작성 기준: 2026-11-05, 한국 시간. 제품과 역할은 제안이며 실제 공모전 심사 기준이나 심사위원 의견을 대변하지 않습니다.

## 핵심 제안

고령자와 초보 운전자가 출발 전에 이해하기 쉬운 경로와 차량 사용법을 준비하고, 주행 중에는 검증된 상황에만 최소한의 안내를 받도록 돕는 차량 내 서비스. 고령자/초보자는 편의 프리셋이며 개인 능력을 추정하지 않고 모든 항목을 직접 바꿀 수 있다. 앱은 운전자 보조 정보이며 운전자와 차량의 경고·판단을 대체하지 않는다.

## 1. 데이터 연동 전략과 실현 가능성

표기: **공식 근거**는 SDK 문서에 명시된 기능 범위, **확인 필요**는 정확한 API·권한·배포 상태·차종에서의 지원 확인이 필요한 구상이다. 지원이 확인되지 않은 데이터는 추정하거나 임의의 수치로 대체하지 않는다.

| 항목 | 연동 및 UX 제안 | 근거·제약과 대체 동작 |
|---|---|---|
| 사용자 유형·화면 | 고령자에는 큰 글자·대비, 초보자에는 출발 전 상세 설명을 기본값으로 제안. 커스텀 선택은 사용자가 변경. | 사용자 유형과 글자 크기의 기기 내 저장 및 유형별 글자 크기 초기값 적용을 구현. 대비·음성·안내 등 나머지 프리셋은 별도 작업. 프로필만으로 시력·운전 능력 추정 금지. |
| 주간·야간·대비 | 시스템 테마를 우선 따르고 수동 선택 제공. 차량 조도 데이터가 실제 승인되면 자동 변경 검토. | 조도 센서 접근은 **확인 필요**. 미지원이면 시스템/수동 설정만 제공. |
| 음성 속도·음량 | 주차 중 미리 듣기와 속도 조절, 재생 시 차량 오디오 포커스와 공존 정책 확인. | Pleos TTS/STT는 공식 안내상 준비 중. Android TTS·오디오 포커스 대안은 기기·심사 정책과 음성 엔진 확인 필요. 속도·차량 오디오 볼륨에 따른 자동 조정과 더킹 제어 가능 여부는 **확인 필요**. 앱이 임의로 차량 전체 음량을 바꾸지 않는다. |
| 큰길 우선·고속도로 선호 | 출발 전 두 선호를 별도로 표현하고, 제공 가능한 경로·소요 시간·확인된 부담 요소를 비교한다. | NaviHelper는 목적지·경유지, 경로 옵션 변경·재탐색, 이벤트를 안내한다. **도로 폭·차로 수, 어려운 교차로, 독립 옵션 및 대안 경로 점수의 제공 여부는 미확인.** SDK가 제공하는 옵션만 실제 적용하고 나머지는 연동 전 비활성화. 정확성·라이선스를 검증한 지도 데이터가 없다면 부담 점수를 산출하지 않는다. |
| 복잡한 교차로·차선 변경 | 위치/경로 이벤트와 안내 내용이 검증되는 경우 운전자에게 사전 안내. 출발 전 상세 미리 보기, 주행 중 최소 정보. | NaviHelper 안내 이벤트의 종류·시점·차선 정보는 **확인 필요**. 정보 미제공 시 차량 내비 기본 안내만 사용하고 앱이 차선 변경을 유도하지 않는다. |
| 차량 조작 따라 배우기 | P단 확인 후 공조·김서림 제거·와이퍼 연습을 시작. 실제 상태 변경 이벤트와 요청한 상태가 일치할 때만 완료 표시. | Vehicle SDK는 HVAC/Wiper 및 capability/get/callback을 문서화. P단/정지 판단, 조작별 데이터·권한·차종 지원은 **확인 필요**. 판단 불가·연결 끊김·주행 전환 시 실습 중단. 상태를 알아내지 못하면 수동 확인을 완료로 오인하지 않는다. 차량 제어 SDK는 준비 중이므로 앱에서 차량 조작을 실행하지 않는다. |
| 경고등 설명 | 지원되는 경고 이벤트를 받아 공식 매뉴얼의 검증된 코드·차종·연식에 일치하는 설명만 연결. | Safety 도메인은 경고 조회 범위를 명시하나 실제 경고 종류·심각도·제공 범위는 **확인 필요**. 미매칭·오래된 데이터는 '상세 확인 불가', 차량 계기판·공식 매뉴얼 우선. 차량 본래 경고를 대체하거나 지연하지 않는다. |
| 위험 상황 알림 | 지원되고 승인된 이벤트만 최소 정보로 안내하는 것을 검토. | 후측방 센서·ADAS 실시간 위험·차선 변경 가능 여부·접근 권한은 **확인 필요**. 실시간 충돌/사각지대 판단이나 안전 보장을 주장하지 않는다. |
| 개인별 복습 | 사용자가 선택한 연습 항목·완료 여부·사용자 설정을 기기 내 저장하도록 설계. 다음 탑승 시 주차 중 보여준다. | 저장소 구현·사용자 분리·보관 기간·삭제 UI 필요. 경로 이력이나 차량 식별자 없이 최소 정보만 저장. 실제 구현 및 검증 전 계획. |

공통 파이프라인: 서비스 연결 → 필요 권한과 `checkXXXCapabilities` 확인 → 유효한 이벤트 수신 → 최신성·지원 상태 확인 → 운전 상태와 주행 제한 정책 확인 → 중요도·중복 억제 → 짧은 화면/음성 안내. 연결 실패·권한 거부·미지원·오래된 값은 분리하여 표시한다. 앱 자체 안내는 차량의 안전 경고를 가리거나 덮어쓰지 않는다.

## 2. 사용자 유형별 시나리오

시나리오는 구현 목표이며, P/D 판별 및 내비/경고 이벤트가 허용·지원되고 실제 기기에서 검증되는 것을 전제로 한다. 사용자 유형은 개인이 바꿀 수 있는 초기값이다.

| 상황 | 고령자 프리셋 | 초보자 프리셋 | 공통 안전 규칙과 실패 대안 |
|---|---|---|---|
| 출발 전·주차 상태 | 큰 제목, 높은 대비, 한 번에 하나의 선택. '목적지와 경로를 확인해 주세요'처럼 짧고 천천히, 사용자가 요청하면 반복. 연습은 단계별 큰 그림. | 목적지·시간과 확인 가능한 부담 요소를 비교하고 어려운 구간을 출발 전 미리 설명. '진입 전에 표지판을 확인하세요'처럼 이유를 포함한 연습 안내. | 주차 상태를 신뢰성 있게 확인해야 상세 실습을 연다. 미확인이면 잠그고 차량 계기판 및 매뉴얼을 확인하도록 안내. 시간/점수/안내는 실제 데이터가 확인될 때만 표시. |
| 주행 중·복잡한 교차로/차선 변경 | 한 화면에 현재 안내 한 건, 큰 글자·짧은 문장. '곧 우회전 안내가 있어요'처럼 이벤트가 실제 제공할 때만 발화. | 실제 내비 이벤트가 제공하는 범위 안에서 사전 맥락을 짧게 제공. 예: '곧 분기점이 있습니다. 표지판을 확인하세요'. | 주행 중 긴 텍스트·설정·학습 조작 제한, 주행 제한 정책 우선. 차선 안전 여부를 판정하지 않고 확인되지 않은 시간·거리·차선 지시를 생성하지 않는다. 정보가 없으면 시스템 내비 안내를 따른다. |
| 경고 발생 | 기존 차량 경고를 가리지 않는 범위에서 큰 경고명과 쉬운 한 문장, 확인된 경우에만 검증된 안내. | 동일 경고를 제공하되 차량이 정차한 뒤 확인할 수 있는 상세 설명·매뉴얼 연결을 제공. | 긴급도 임의 판정 금지. 데이터/매뉴얼 매칭 실패 시 세부 설명을 단정하지 않고 차량 기본 경고와 공식 매뉴얼을 우선. 주행 중 복잡한 조작을 요구하지 않음. |

오디오 발화는 최종 서비스 지원과 정책 확인 전 **UX 예시**이며, 실제 TTS가 연결되어 있다는 뜻이 아니다. 안전 필수 경고는 사용자 알림 최소화 설정으로 억제하지 않는다.

## 3. 통합 정보 구조(IA)

```text
앱 시작
├─ 최초 설정: 사용자 유형 선택 [고령자 / 초보자 / 직접 설정]
│  └─ 프리셋 내용 확인 및 수정 (음성 실행은 플랫폼 지원 확인 후)
├─ 홈
│  ├─ 경로 준비 [출발 전]
│  │  ├─ 목적지 검색 / 경유지
│  │  ├─ 경로 비교: 소요 시간 / 제공되는 부담 요소
│  │  └─ 복잡한 진입·교차로 미리 보기 (데이터 제공 시)
│  ├─ 차량 조작 배우기 [주차 상태 확인 후]
│  │  ├─ 공조 / 김서림 제거 / 와이퍼
│  │  └─ 단계 안내 → 실제 상태 확인 → 완료 또는 재시도
│  ├─ 경고등 도움말
│  │  ├─ 지원되는 현재 경고 (미연결 상태 별도 표시)
│  │  └─ 확인된 공식 매뉴얼 설명 / 대응 안내
│  ├─ 내 복습 [주차 중 상세 확인]
│  │  └─ 미완료 연습 / 다시 볼 항목 / 기록 삭제
│  └─ 설정
│     ├─ 사용자 유형: 고령자 / 초보자 / 직접 설정
│     ├─ 화면: 글자 크기 / 테마·색상 / 대비 / 주간·야간
│     ├─ 음성: 언어 / 음성 종류 / 속도 / 음량
│     ├─ 안내: 안내 빈도 / 주행 중 최소화 / 차선 변경 사전 시점 /
│     │          복잡한 구간 사전 안내 / 지원되는 위험 알림
│     ├─ 경로 선호: 큰길 / 고속도로 (각각 별도)
│     └─ 데이터: 설정·복습 삭제 / 개인정보 안내
└─ 주행 중: 허용된 경우 현재 안내와 필수 상태만 제공
```

안내 빈도는 한 곳에서 관리한다. 설정·복잡한 비교·학습·복습 상세는 주차 중 접근을 원칙으로 하고, 실제 노출은 지역·차량 주행 제한 정책에 따른다. 차량 상태 확인이 불가능하면 제한 기능을 보수적으로 잠근다.

## 4. 1차 기획서용 핵심 어필 3가지

1. **접근성을 차량 경험의 기본값으로.** 고령자와 초보자가 글자·대비·안내 길이를 직접 조정해 같은 기능을 이해할 수 있다. 연령 자체가 아니라 사용자가 고른 요구에 맞춘다. 검증 지표: 참여자별 출발 전 과제 완료율과 도움 요청 횟수·주관적 이해도(실측 필요).
2. **사용법 설명을 실제 차량 상태와 연결.** 단순 문서가 아니라 주차 상태에서 허용된 차량 이벤트를 확인하는 연습으로 이어진다. 완료 판정과 지원 여부를 명시해 재현 가능한 시연을 만들고, 반복 문의나 사용 부담 감소 가능성을 평가한다. 검증 지표: 연습 완료율, 첫 시도 성공률, 재시도 횟수(실측 필요).
3. **기존 내비·차량 경고를 존중하는 SDV 서비스.** 제공되는 NaviHelper·Vehicle State 범위에 맞춰 차량별 지원 여부를 확인하고, 미지원 기능은 안전하게 제한한다. 사용자가 설정을 보존·삭제할 수 있도록 최소 수집 원칙을 제안해 신뢰와 접근성을 제품 차별점으로 만든다. ESG 효과는 도입 가능성으로 제시하고 실제 안전 개선은 비교 실험 전 확정하지 않는다.

## 1차 제출 및 구현 순서

- 접수: 2026-10-21~11-15 KST. 접수양식/기획서는 필수, 시연 영상과 소스·APK는 선택이며 제공 수준에 따른 가산점이 안내됨. 2차 PT 대상은 PT 전 실제 동작 앱 필요. [제출 방법](https://appdevchallenge.auto-hmg.io/guide/submission), [일정](https://appdevchallenge.auto-hmg.io/guide/schedule).
- 1차: 사용자 유형·설정·주차 전용 실습 화면과 미연결 상태를 명시한 프로토타입. 사용자 유형과 글자 크기 저장 및 글자 크기 프리셋을 구현했으며 실제 에뮬레이터에서 변경 사항의 검증이 필요. 공식 에뮬레이터에서 팀이 직접 시연을 검증한다.
- 2차: 지원·권한이 확인된 Vehicle State와 NaviHelper를 연동하고 실패·미지원 시나리오를 재검증. 설정 복원은 팀원이 별도 구현. TTS, 차로 데이터, ADAS, Vehicle Control은 제공 상태 확인 전 확정 범위에 넣지 않는다.
- 확인 지표: 대표 과제 성공률, 주요 안내 이해도, 실습 완료율, 주행 중 불필요한 상호작용 횟수. 참여자 구성과 측정 방법을 사전 정의하고 결과가 나오기 전 수치를 주장하지 않는다.
