### 1-3. 기능별 구현 순서와 실패 대안

1. **S0 → S1 → S2.** 기존 설정 저장을 기준으로 앱 재실행·기기 재부팅·설정 손상/복원 실패를 시험한다. 화면·설정 분리를 유지한다. 복원이 실패하면 이전 설정을 추측하지 않고 기본값과 재설정 가능 상태를 표시한다. 프로필 변경은 사용자가 선택한 경우만 적용한다.
2. **안전 게이트 우선 → F2.** 먼저 DO·지역·기어·속도·신호 최신성의 조합과 제약 API를 검증한다. 실제 문 상태 조회는 참고 코드일 뿐 와이퍼·공조 연동이 아니다. 와이퍼 또는 공조에서 권한·`check...Capabilities`·대상 영역·읽기/콜백을 검증한 **한 항목만** 고른다. 사용자 직접 조작 전/후 상태를 비교하고 일치하는 이벤트를 받은 경우에만 완료. 미지원·권한 거부·초기 상태 불명·시간 초과면 `확인 불가`, 미완료 처리; 자동 완료하지 않는다. SDK에 없는 API 이름을 이 문서에서 확정하지 않는다.
3. **F2 → F4 → F2.** 사용자가 미완료 저장에 동의하면 최소 데이터(학습 항목 ID, 미완료 상태, 선택 시각/스키마 버전)만 기기에 저장한다. 앱 종료·재실행 후 주차 확인 시 기록을 보여주고 사용자가 선택할 때 연습을 재시작한다. 기록별 삭제·전체 삭제·읽기 실패를 검증한다. 이름, 경로 좌표, 차량 식별자, 감정 추정은 필수 데이터가 아니다.
4. **F1·F3은 병행 조사 후 확장.** F1은 공식 내비 옵션과 콜백을 조사하되 지도 기본 화면 문제와 별도다. F3은 앱에서 실제 받을 수 있는 경고 코드와 공식 매뉴얼 제공 방식이 검증되기 전 UI 예시만 마련한다. F4의 F1·F3 자동 수집은 범위 밖이며 수동 저장도 연동 검증 후 확장한다.
5. **S3·S4.** 프리셋·설정 화면 목업은 가능하나 음성 출력과 실제 사전 안내는 지원·정책 확인 전 확장한다. 단순히 메뉴나 선택값이 있다는 사실을 실제 음성·안내 기능 완성으로 말하지 않는다.

**재진입·정체성.** F4는 `user_slot=local_demo` 하나를 쓰는 단일 사용자 시연 [가정]으로 구현한다. 이 슬롯은 신원과 무관하다. 다른 사람이 같은 차량을 이용할 수 있다면 개인별 자동 복원이라고 말하지 않고, 사용자 선택·혼동 방지·삭제와 실제 다중 사용자 모델을 검증할 때까지 다중 사용자 확장은 막는다. F4→S1은 사용자가 주차 중 제안을 확인·동의해야만 적용하며, 12월 MVP의 필수 항목이 아니다.

**판단 실패 순서.** SDK가 예외를 던지거나 권한이 없으면 조회 실패, capability가 비어 있거나 미지원이면 미지원, 응답이 제시간에 없거나 값의 시점·기어·속도가 모순되면 확인 불가로 구분한다. 자동으로 이전 값이나 0을 대신 사용하지 않는다. 안전 잠금 해제 시 차종·권한·상태를 다시 검사한다.

### 1-4. P·D·미확인·경고 전환 규칙

| 관찰 상태 | MVP 동작 | 예외·우선순위 |
|---|---|---|
| P + 속도 0 + 최신 상태 + 해당 정책이 주차 작업을 허용 | S1/S2 설정, F2 한 항목, F4 저장·복원·삭제 허용 **목표**. 필요한 세부 신호와 권한이 확인되지 않으면 이 행으로 진입하지 않는다. | 기어·속도뿐 아니라 실제 플랫폼의 주행 제한 상태를 확인한다. 플랫폼 버전/지역 규정 우선. |
| D, 주행 제한 활성, 또는 속도가 움직임을 나타냄 | F2 실습·복잡한 설정·F4 상세 잠금 및 진행 중 연습 중단. 현 문서의 MVP는 주차 시연이므로 주행 중 앱 안내는 보장하지 않음. | 정차 여부는 D만으로 확정하지 않는다. DO 미선언일 때 공식 정책은 Parking 사용 가능·Drive 사용 불가를 기본으로 명시. DO 선언만으로 승인이나 모든 동작이 보장되지는 않음. |
| 기어/속도/주행 제한·연결 중 하나가 미확인·오래됨·상충 | F2와 복잡한 설정 잠금, `차량 상태 확인 불가`; 완료 처리 금지. 사용자가 저장에 명시 동의한 연습은 F4에 미완료로 보존. | 시뮬레이터 전용 SIM은 실제 안전을 입증하지 않는다. 단절이 해소되면 새 신호를 재검사한다. |
| 차량 경고 발생 | 차량 본래 경고가 최우선. F3은 허용·검증된 경우만 보조 설명; 상세 보기·복습 저장은 주차 후. | F3 미지원·경고 코드 미매칭 시 `상세 확인 불가`; S4는 필수 차량 경고를 끄거나 늦추지 않는다. |

[주행 규제 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)은 DO 미선언 시 주차 허용·주행 불가의 기본 규칙과 지역별 제한을 기술한다. [주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline), [앱 카테고리](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category)는 일부 지도·내비 기능의 제한적 허용 가능성을 설명하지만, 이 앱의 분류·승인·구체적 화면/음성 허용 여부는 [확인 필요]다. **현재 앱에는 위 잠금이 아직 없다.**

## PART 2. 김영희와 이준의 한 번의 운행

아래 음성 문장은 **UX 예시**다. Pleos TTS는 준비 중이고 실제 재생·음성 종류·오디오 포커스·음량·정책이 확인되지 않았다. S3의 속도·음량은 사용자가 조절하는 값을 기준으로 하며 임의의 dB·자동 증폭 수치를 확정하지 않는다. D단 표시만으로 움직임을 확정하지 않는다.

| 구간·기능 ID | 김영희: 화면 / 음성 예시·속도·음량 | 이준: 화면 / 음성 예시·속도·음량 | 신호·범위·조건 |
|---|---|---|---|
| ① 탑승·출발 전: S0, S1, S2, F2, F4 | P 확인 후 큰 글씨로 유형·미완료 연습을 한 번에 하나씩. 음성 예시: “지난 연습을 이어서 볼까요?” 사용자가 고른 느린 속도·미리 듣기로 조절한 음량. | P 확인 후 단계 목록·예상 작업과 미완료 항목을 제시. 음성 예시: “와이퍼 조작을 한 단계씩 연습해요.” 속도·음량은 본인 설정. | [확인 필요] P·속도·제한·권한·F2 신호. **MVP 목표:** 설정/단일 연습/F4. 음성은 확장. 미확인 시 F2 잠금. 연결: [S0]·[S1]·[S2] ← 기기 설정·사용자 / → [F2]·[F4]. |
| ② 주행 중 복잡한 교차로: F1, S1~S4 | 앱이 정책상 허용되는 경우에 한해 큰 글씨의 한 건. 음성 예시: “앞쪽 안내를 확인해 주세요.” 속도·음량은 본인 설정. | 허용·실제 내비 이벤트 확인 시 짧은 사전 맥락. 예: “곧 갈림길이 있습니다. 표지판을 확인해 주세요.” 본인 속도·음량. | **확장·조건부 [확인 필요]:** DO, 지역·카테고리·이벤트, 교차로 세부 데이터. 미승인/DO 미선언에서는 앱 표시·발화 보장 불가. 운전 중 조작 요구 없음. 연결: [F1] ← 내비·[S1~S4] / → [F4]는 주차 후 사용자가 선택한 항목만. |
| ③ 주행 중 차선 변경: F1, S1~S4 | 실제 지원 시 필수 정보만 시각·음성으로 짧게. 예: “내비게이션 안내를 확인해 주세요.” 본인 속도·음량. | 실제 지원 시 출발 전 정의한 설명 밀도 적용. 예: “앞쪽 분기 안내가 있습니다.” 본인 속도·음량. | **확장·조건부 [확인 필요]:** 차선/안내 시점 신호·권한·주행 허용. 안전한 차선 변경이나 사각지대를 판단했다고 말하지 않음. 연결: [F1] ← 확인된 내비·[S1~S4] / → [F4] 사용자 선택 확인 항목. |
| ④ 경고 발생: F3, S1~S4 | 차량 자체 경고를 우선. 허용되고 코드·매뉴얼이 맞을 때만 큰 경고명, 예: “차량 안내를 확인해 주세요.” 사용자가 고른 속도·음량. | 차량 자체 경고를 우선하고, 확인된 상세 설명은 정차 후 제공. 같은 일반 문장 사용 가능. | **확장·조건부:** Safety 범주 [공식 문서 확인], 세부 경고·매칭·DO·음성 [확인 필요]. 미일치면 상세 확인 불가. 일반 알림 설정으로 차량 경고 억제 금지. 연결: [F3] ← 검증된 경고·[S1~S4] / → [F4] 사용자가 고른 다시 보기. |
| ⑤ 정차·다음 탑승: F2, F4, S0, S1 | 새 주차 확인 후 미완료 목록에서 본인이 선택한 연습 다시 시작. 예: “이어서 연습할까요?” 속도·음량 본인 설정. | 미완료 단계와 재시작 버튼을 보여주고 스스로 선택. 예: “남은 연습을 다시 시작해요.” 본인 설정. | **MVP 목표:** F2 미완료 저장·재실행 복원·삭제. F4→F1/F3·S1 제안은 확장. 재탑승 자동 인지·신원 분리는 [확인 필요]. 연결: [F4] ← 사용자 동의한 [F2] 미완료 / → 사용자가 선택한 [F2] 재시작. |

F4는 다음 앱 실행에서 `local_demo` 슬롯의 저장된 F2 미완료 기록을 복원하되, 개인 신원을 추정하지 않는다. 확인된 주차 상태에서 사용자가 눌렀을 때만 F2로 이동한다. F1/F3 저장 및 재진입, F4가 S1을 제안하는 기능은 확장이다. 제안을 표시하더라도 **주차 중 명시 동의 전 S1을 바꾸지 않는다.**

## PART 3. 통합 정보 구조와 연결

### 3-1. 메뉴 트리

태그: `[P단만]`은 **P와 속도·최신성·플랫폼 정책이 함께 확인된 경우에만** 가능한 목표다. `[D단만]`은 D에서만 고려할 수 있는 **확장 구상**으로 현재 실행이 보장되지 않는다. `[상시]`는 앱/플랫폼이 실제 허용하는 시간 동안 상태 확인·안내를 수행한다는 뜻이지 DO 미선언 앱이 주행 중 실행된다는 뜻이 아니다. `[MVP]`는 목표, `[확장]`은 미검증 범위다. `unknown`은 F2와 복잡한 설정을 잠근다.

```text

├─ S0 설정 불러오기 [상시][MVP]

│  │  └─ F1/F3 재진입·S1 제안 [P단만][확장]
```

차량 상태 확인 불가 시 S0는 원인을 설명하고 F2·복잡한 설정을 잠근다. 앱 자체가 주행 정책으로 제한될 수 있으므로 이 화면이 주행 중에 반드시 보인다고 약속하지 않는다. 기획의 S1→S3/S4는 향후 설정이 실제 제공될 때만 적용한다.

### 3-3. 주요 화면 흐름 세 가지

1. **온보딩 → 프로필:** S0 실행·설정 복원 → 차량 상태/플랫폼 허용 확인 → S1 고령자·초보자·직접 설정 → S2 글자 크기 확인/수정 → 저장 → 홈. 정보가 없으면 잠금·확인 불가. S3/S4 기본값은 기능 검증 전에는 안내만 한다. **연결: [S1] ← [S0]·사용자 선택 / → [S2~S4]·[F1~F4]의 기본 표현.**
2. **경로 준비 → 내비 요청:** 주차 확인 → F1 목적지 → 사용자가 독립 선호 입력 → 실제 NaviHelper가 지원하는 단일/복합 옵션 확인 → 선택한 요청 → 콜백 결과를 확인된 범위에서 표시 → 사용자가 F4에 확인 항목 저장 선택. 도로 폭·차로·두 옵션 동시 적용 미지원 시 주장/대체 점수 없음. 전 과정 12월 확장. **연결: [F1] ← [S1~S4]·내비 결과 / → [F4] 사용자가 선택한 항목.**
3. **경고 → 주차 후 상세 → 복습:** 차량 자체 경고 우선 → 지원된 F3 경고 확인 또는 상세 확인 불가 → 주차·제약 확인 → 검증된 차종/연식 매뉴얼 상세 → 사용자가 다시 보기를 선택하면 F4에 기록 → 다음 탑승에서 선택 시 F3 재진입. 이 전 과정은 실경고 연동 확인 전 확장이다. **연결: [F3] ← 지원된 경고·[S1~S4]·[F4] / → [F4] 사용자가 고른 설명.**

### 4-1. 차별성 세 가지

**① 헤드카피: “차량의 상태를 확인하고, 이해할 수 있는 말로 돕습니다.”**

근거: [공식 문서 확인] Vehicle State SDK는 영역별 상태 조회·capability와 콜백을 설명하고 Virtual Console은 와이퍼·공조 등 상태 변화를 제공한다. P단과 선택한 F2 신호의 실제 API 접근은 [확인 필요]다. 차량 자체의 제어·경고를 대체하지 않아 플랫폼 기능과 결합 가능한 서비스 시나리오를 제안한다. **현대차·기아/Pleos 가치:** 차량 특화 기능의 이해와 접근성을 높이는 후보 경험으로 평가할 수 있다. **예상 질문:** “스마트폰 튜토리얼과 무엇이 다른가?” **답:** “지원·권한이 확인된 차량 상태 변화가 들어올 때만 학습 완료를 판정하고, 신호가 없으면 확인 불가로 남깁니다.” 검증 전 실제 차량 적용·완료율·사고 감소는 주장하지 않는다 [실측 필요].

**② 헤드카피: “한 번의 설명이 아니라 다음 탑승까지 이어지는 복습.”**

근거: 사용자 동의를 받은 F2 미완료를 기기에서 보관하고, 재실행·주차 확인 후 본인이 선택해 이어간다. **③ 헤드카피: “12월에 보여줄 수 있는 한 가지 완결된 실습.”**

근거: MVP는 유형/글자·주차 게이트·F2 한 항목·F4 재실행 복습·예외로 제한한다. 기어 확인과 와이퍼/공조 콜백이 되는지 지금 검증하고 미지원은 명시적 SIM 대안으로 전환한다. **가치:** 플랫폼 적합성과 단계별 확장 가능성을 거짓 데이터 없이 설명한다. **예상 질문:** “API가 미지원이면 실패한 시연 아닌가요?” **답:** “기기에서 확인된 SDK 수신과 별도 시뮬레이션을 화면에 구분하고, 확인 불가일 때 완료 처리가 막히는 동작까지 보여줍니다. 실제 신호 검증 여부도 함께 명시합니다.” 주행 중 운전자 안전 개선 수치는 [출처 확인 필요/실측 필요].

| 항목 | 점검 결과 | 부족한 부분과 수정·검증안 |
|---|---|---|
| 1. F1~F4·S0~S4가 PART 1~3에 등장 | 충족: 기능표·시나리오/설명·IA에서 ID 사용. S0는 PART 2의 탑승/다음 탑승에 포함. | 실제 기능별 코드 구현 여부와 기획안을 계속 분리. |
| 2. S1 허브·F1~F3→F4→다음 탑승 | 기획 연결 완료. MVP의 실제 구현은 아직 아님. | 12월에는 F2→F4→F2만 우선 구현. F1/F3 및 F4→S1 제안은 확장, 사용자 동의 필수. |
| 3. 상태별 잠금과 경고 우선 | 문서 규칙 정합: P+조건 확인, D/unknown 잠금, 차량 경고 우선. | 현재 코드에는 주차/DO 게이트가 없다. 신호 접근·플랫폼 정책을 확인해 구현하기 전 MVP 안전장치 완성이라고 주장 금지. |
| 4. 실제·미확인·시뮬레이션 구분 | 출처/신뢰도 태그와 실패 대안 정의. | 실제 Pleos 기기/에뮬레이터 API 응답 미검증. SIM은 에뮬레이터 전용·배지 필수, 실차 안전 판단 금지. |
| 5. 인력 구성 | 개발자 3명 공동 개발, 디자이너 2명 공동 디자인. | 개인별 담당은 미배정. 필요 시 팀이 별도로 정함. |
| 6. 12월 범위 | F2 한 항목과 F4 복습, S1/S2 및 실패 흐름으로 축소. | P 게이트·SDK 신호·F4 저장은 아직 미구현/미검증. 우선순위 검증 후 사용 불가면 명시적 SIM 시연; 일정은 보장할 수 없음. |
| 7. 자동 프로필 변경·미확인 사실 | F4→S1 제안은 주차 중 명시 동의 후에만 반영. 신원은 유형과 구분. | 기기 다중 사용자 식별·복습 격리는 확장. 미확인 값은 `확인 불가`로 유지하고 실제처럼 채우지 않음. |
