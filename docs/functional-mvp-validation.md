# 기능 구현 및 Pleos 에뮬레이터 확인

2026-11-06. 이번 변경은 F2 와이퍼 연습, F4 복습, 경로 선호 저장 및 주차 확인을 구현한다. 전체 기획의 완료를 의미하지 않는다.

## 구현 범위

- 실제 앱 진입점 `MainActivity → ParkedApp`은 Android Car 서비스의 기어 P, 속도 0(오차 0.01 m/s 이내), UX 제한 없음이 모두 확인될 때만 화면을 제공한다. 750ms 간격으로 다시 읽고 마지막 성공한 읽기가 2.5초를 넘으면 제한한다. 읽기는 IO에서 수행하며 독립적인 200ms 감시 루프가 갱신 지연을 감지한다. 백그라운드 전환·연결 실패·권한 거부 때 확인값을 폐기한다. 운전 중 앱 이용을 허용하는 DO 선언은 추가하지 않았다.
- 주차가 확인되는 동안 Pleos Vehicle SDK의 앞유리 WiperState 지원 영역, 읽기 권한과 OFF/ON 지원을 확인한다. `OFF → ON → OFF` 순서만 완료한다. 이미 켜진 상태, OTHER/SERVICE, 응답 없음은 완료가 아니다. 신호가 끊기면 순서도 처음부터 확인한다. 차량 조작 명령은 없다.
- 복습 저장 동의 시 시작 즉시 미완료 기록, 성공 시 완료 기록을 저장한다. 앱 종료/화면 이탈/주차 제한 후에는 처음부터 다시 연습한다. 동의 철회는 기록 삭제와 함께 적용한다. 내 복습에서 재시작, 삭제 확인, 재실행 복원이 가능하다. 한 기기의 한 사용자만 가정한다.
- 복습 기록은 클라우드 백업과 기기 이전에서 제외한다. 데이터 출처는 에뮬레이터 식별 시 `EMU_SDK`, 그 외에는 실차 여부 미검증으로 표시한다. 모의 성공 상태를 제공하지 않는다.
- 큰길/고속도로 선호를 독립 저장한다. 기본 UMOS 내비게이션의 실행 가능한 Activity가 있으면 연다. 아직 경로 계산에 선호를 전달하지 않는다.

## Windows에서 확인

Android Studio Terminal에서 `git pull --ff-only` 후 ▶ Run. 처음 요청하는 차량 속도 읽기 권한을 허용한다. 모든 테스트는 가상 차량에서 시행한다.

1. Virtual Console에서 P, 속도 0으로 설정한다. 앱 홈이 열리는지 확인한다. P인데 제한 화면이 유지되면 화면에 표시된 주차/속도/화면 허용 값과 앱 권한을 확인한다. 미지원 서비스에서는 우회해서 실행시키지 않는다.
2. 차량 조작 배우기 → 복습 저장 동의 → 연습 시작. 앞유리 와이퍼를 꺼짐/작동/꺼짐으로 바꾸며 각 상태를 3초 이상 유지한다. 콘솔의 스위치 입력이 실제 WiperState에 반영되는지는 에뮬레이터에서 확인이 필요하다. 스위치만 바뀌고 상태가 안 바뀌면 완료되지 않는 것이 맞다.
3. 이미 와이퍼가 켜진 상태로 시작하거나 SDK가 지원하지 않는 상태를 넣어도 완료되지 않는지 확인한다.
4. 연습 중 D단이나 0보다 큰 속도로 바꾸면 화면이 제한되는지 확인한다. P/0으로 돌아와 내 복습에 미완료가 남는지 확인한다. 이전 단계부터 자동 재개하지 않는다.
5. 미완료 연습 후 앱 종료/재실행 → 홈 복습 알림 → 재연습. 완료하면 내 복습에 완료 및 출처·시각이 표시되는지 확인한다.
6. 기록 삭제 취소/확정 및 동의 철회 후 재실행 시 기록이 없는지 확인한다.
7. 경로 선호 둘을 서로 다르게 저장한 뒤 재실행해 유지되는지 확인한다. 기본 내비게이션 실행 실패 시 안내 문구가 나오는지 확인한다.
8. 고령자/초보자 글자 크기 변경이 제목·본문·버튼에 적용되는지 확인한다.

## 검증 한계 및 다음 연결

클라우드에서 APK 빌드, JVM 단위 테스트, Android 계측 테스트 APK 컴파일을 수행한다. 실제 계측 테스트 실행과 Pleos 런타임 확인은 Windows 에뮬레이터가 필요하다. JVM에서는 완료 순서, 신호 유실, 주차 조건/만료/비정상 속도를 검증하고, 계측 테스트에는 저장 동의·복원·삭제와 경로 설정 독립 저장 검증을 추가했다.

폴링 사이의 차량 변화는 즉시 감지되지 않을 수 있으며 Car 서비스가 반환한 현재 값을 기준으로 한다. 실차 안전 보증이나 제어 인터록이 아니다. 앱은 SDK 읽기만 수행하며 Pleos Virtual Console의 문 잠금/열림 동작을 바꾸지 않는다.

아직 미구현: NaviHelper 경로 비교/실제 큰길 반영, 자동 경고등 구독 및 차량별 매뉴얼 콘텐츠, 음성 안내와 오디오 연동, 공조 실습, 다중 사용자. UMOS 기본 내비게이션 상세 지도 누락도 이 변경으로 해결되지 않는다.

## 사용자 모드 및 화면 설정 후속 구현

- 고령자 프리셋: 큰 글자(기존 1.4배), 높은 대비, 간단한 안내. 홈에는 경로 준비/차량 조작 배우기/내 복습/더 보기만 표시한다. 사용자 유형과 설정은 더 보기에서 접근한다.
- 초보자 프리셋: 보통 글자, 기본 대비, 상세 안내. 홈의 출발 전 설명과 와이퍼 연습 순서 설명을 추가한다. 안전·연결 상태 안내는 두 모드 모두 유지한다.
- 직접 설정: 글자 크기, 대비, 안내 상세도, 주간/야간/기기 설정을 바꾸면 즉시 적용·저장되고 사용자 유형은 직접 설정이 된다. 기기 설정은 Android의 다크 모드를 따르며 차량 조도 센서 연동은 아니다.
- 프로필 전환은 경로 선호와 주간/야간 선택을 유지한다. 이전 버전에서 고령자로 저장한 사용자는 신규 대비/상세도 설정이 없을 때 고령자 기본값을 적용한다.
- 일반 텍스트뿐 아니라 카드·버튼·배경에 선택한 테마를 적용한다. 홈/설정 버튼은 넓이가 부족하면 다음 줄로 이동한다. 시스템 뒤로가기는 홈으로 이동한다.
- 확인: 고령자 선택 → 홈 간단 구성 → 더 보기 → 설정 → 주간/야간·대비 변경 → 앱 재실행 후 유지 확인. 초보자 선택 후 상세 홈과 연습 설명 확인. 클라우드는 빌드와 단위 테스트를 실행하며 계측 테스트는 컴파일만 수행한다.

## 글자 크기 슬라이더·음성 입력

글자 크기는 100~200% 슬라이더로 변경하며 손을 놓으면 저장한다. 사용자 유형과 독립적으로 유지된다. 음성 버튼은 Android의 외부 음성 인식 Activity가 설치되어 있을 때만 활성화된다. Pleos 자체 STT SDK 연동이나 에뮬레이터 음성 서비스 제공을 의미하지 않는다. 인식 서비스가 없거나 실행 실패/취소/잘못된 숫자일 때 기존 크기를 유지한다. 예: “글자 크기 150퍼센트로 바꿔줘”, “이백 퍼센트”. 명시적인 100~200 사이 숫자 하나만 허용한다.

음성 결과 수신은 주차 제한 UI 바깥의 Activity 생명주기에 둔다. 인식 화면으로 이동하면서 앱이 일시 중지되어도 결과를 저장하고, 화면 재진입 시 주차 조건을 다시 검사한다. 앱 내 설정은 저장 변경을 구독한다. Windows에서 마이크 전달과 인식 서비스 작동은 별도 확인이 필요하다.
