# 기능 구현 현황 및 Pleos 확인 방법

2026-11-06 KST 기준. 기획 문서의 목표와 실제 코드 구현을 구분한다. 아래 기능은 코드·빌드 검증까지 완료했으며 Windows Pleos 2.1.0의 새 기능 실행 검증은 아직 수행하지 않았다.

## Windows에서 실행

Pleos 에뮬레이터를 하나 켜고 Android Studio Terminal에서:

```powershell
git pull --ff-only
.\run-app.cmd
```

스크립트는 현재 터미널에만 Android Studio JBR/SDK 기본 경로를 적용하고 빌드 → 기존 데이터 유지 설치 → 앱 재실행을 수행한다. 에뮬레이터 선택이나 빌드/설치가 실패하면 중단한다. Android Studio나 SDK를 다른 폴더에 설치했다면 JAVA_HOME/ANDROID_HOME을 해당 위치로 설정해야 한다. Linux 클라우드에서 Windows 배치 파일 자체를 실행하지는 못했다.

## 구현한 기능

| 화면 | 동작 | 제약 |
|---|---|---|
| 사용자 유형 | 고령자: 큰 글자·높은 대비·간단한 홈, 초보자: 상세 홈·연습 설명 | 자동 음성 안내/ADAS는 포함하지 않음 |
| 글자 크기 | 100~200% 슬라이더, 놓으면 적용·저장. 제목/본문/버튼에 반영 | 직접 선택한 크기는 유형 전환 시 유지. 기본 크기로 복귀 가능 |
| 음성 크기 변경 | “글자 크기 150퍼센트로 바꿔줘”, “이백 퍼센트” 처리 | Android 외부 인식 Activity가 있는 기기에서만 활성화. Pleos STT SDK 연동 아님 |
| 화면 설정 | 주간/야간/기기 설정, 대비, 상세도 저장 | 기기 설정은 Android 다크 모드. 조도 센서 연동 아님 |
| 설정 관리 | 파일 저장·가져오기·복원 확인·초기화 확인 | 버전/값/크기 검증 후 전체 적용. 차량·복습 데이터는 파일에 포함하지 않음 |
| 출발 전 점검 | 안전벨트/거울·좌석/문/목적지/조작 5개 직접 체크 | 센서 확인과 분리. 주차 확인 해제·재시작 시 초기화. 안전 보증 아님 |
| 와이퍼 연습 | SDK OFF → ON → OFF 확인 시 완료 | 지원 영역/읽기 권한 확인. OTHER/SERVICE/미확인 상태에서는 완료하지 않음 |
| 내 복습 | 동의 기반 저장, 미완료 재연습, 최근 20건 시작·완료 이력, 삭제 | 한 기기 한 사용자. 동의 철회 시 기록·이력 삭제. 클라우드 백업/기기 이전 제외 |
| 차량 상태·경고 | 4개 문 열림/잠금, 앞 왼쪽 좌석 벨트 경고, 워셔액 경고 조회 | 마지막 조회값. 전체 경고등 자동 감시 아님. 미지원/권한 부족은 확인 안 됨 |
| 경로 준비 | NaviHelper 연결, 목적지·경로·즐겨찾기 조회, 즐겨찾기로 경로 요청, 옵션 변경, 안내 종료 | 내비게이션 SDK 서비스·권한 필요. 실제 결과 콜백만 완료 표시 |

고령자 홈의 **더 보기**에서 사용자 유형·설정·차량 상태에 접근한다. 화면 버튼은 넓이가 부족하면 줄바꿈하며 시스템 뒤로가기는 홈으로 이동한다.

## 차량·내비게이션 처리 원칙

- 실제 앱 진입은 P·속도 0(오차 0.01m/s 이내)·화면 제한 없음이 모두 확인되어야 한다. 읽기 실패·백그라운드·마지막 성공 조회 2.5초 초과 때 제한한다. 독립적인 200ms 감시와 750ms 간격 조회를 사용한다. 판정 시점의 단조 시계를 사용해 이전 시계 틱 때문에 화면이 깜빡이던 오류를 수정했다.
- Android Car 라이브러리는 선택 사항이다. 없는 이미지에도 설치되지만 주차 상태를 확인하지 못하면 연습/설정 화면을 열지 않는다. 해당 이미지의 Pleos 전용 대체 연동은 아직 없다. 주행 중 사용 허용 DO 선언을 추가하지 않았다.
- 차량 조회에는 제어 API를 호출하지 않는다. 문 열림·잠금 신호를 독립 표시하며 둘이 동시에 보고되어도 문을 자동으로 닫거나 잠금 동작을 변경하지 않는다. 개별 속성의 조회 시각은 다를 수 있고, 잠김이 닫힘을 증명하지 않는다.
- 차량 지원 여부/READ 권한 확인 후 조회한다. 시간 초과·취소 후 도착한 응답이 연습을 완료시키지 않도록 한다. 에뮬레이터 값은 실차 안전 검증 결과가 아니다.
- NaviHelper 3.0.5의 문서화된 API를 사용한다. 경로 변경은 사용자 동작으로만 수행한다. 즐겨찾기로 목적지를 변경하거나 안내를 종료할 때는 화면에서 확인한다. 즐겨찾기 POI 식별자가 부족하거나 좌표가 유효하지 않으면 요청하지 않는다.
- 경로 옵션 변경에는 최근 15초 이내 조회된 활성 안내 상태가 필요하다. 요청 실패/연결 실패/15초 무응답은 성공으로 처리하지 않는다. 무응답 요청이 서비스에서 이미 처리됐을 가능성을 안내한다. 화면을 떠나면 리스너를 해제하고 늦게 도착한 이전 연결의 콜백을 무시한다.
- ‘편안한 경로(COMFORTABLE)’는 도로 폭 데이터 기반 큰길 우선과 동등하다고 표시하지 않는다. 큰길 선호는 저장만 한다. 고속도로 선호는 요청 옵션 초기값에 반영되며 명시적인 적용/요청 동작이 필요하다.
- 음성 인식/파일 선택은 주차 UI 바깥의 Activity 결과 호스트가 수신한다. 외부 화면으로 나갔다 돌아오면 주차를 다시 확인한다. 파일을 읽어도 복원을 확정하기 전에는 기존 설정을 유지한다.
- 필요한 선언 권한 중 기기에 등록된 dangerous 권한만 런타임 요청한다. 거부되거나 지원하지 않으면 해당 데이터는 미확인으로 처리한다.

## 검증 결과

클라우드에서 다음을 성공적으로 실행했다.

```text
assembleDebug
testDebugUnitTest          # 15개 통과
assembleDebugAndroidTest  # 계측 테스트 APK 컴파일만 수행
lintDebug                 # 오류 없음; 의존성 버전·기존 SDK 관련 경고는 남아 있음
```

주요 JVM 검사: 연습 OFF/ON/OFF 순서, 신호 유실, 주차 조건/만료/비정상 속도, 프로필 전환 시 수동 크기 유지, 음성 숫자 파싱 및 범위/모호한 문장 거부, 설정 백업 전체 복원·잘못된 파일 거부, 모순/미확인 문 상태 설명.

계측 테스트: 글자 표시 크기, 슬라이더 200% 및 프로필 전환, 저장 동의·복원·철회·이력 상한/삭제, 기존 설정 마이그레이션과 독립 경로 선호. 이 테스트들은 Windows 에뮬레이터에서 아직 실행하지 않았다.

## Windows에서 남은 확인

1. 앱 업데이트 후 주차 제한 화면과 홈이 안정적으로 전환되는지 확인.
2. 설정에서 슬라이더를 100→200으로 움직이고 놓기 → 프로필 변경 → 앱 재실행 후 크기 유지. 큰 글자에서 설정/홈 버튼에 접근 가능한지 확인.
3. 음성 서비스가 없으면 비활성 안내, 있으면 150/200% 적용, 취소/90/250/모호한 명령은 기존 값 유지.
4. 설정 파일 저장 → 설정 변경 → 파일 가져오기 → 확인 전 유지 → 확정 후 복원. 잘못된 파일/취소도 확인.
5. 출발 전 점검에서 체크/해제·초기화·주차 제한 후 초기화 확인.
6. 와이퍼 상태를 OFF/ON/OFF로 각 3초 이상 유지. 스위치 입력만 있고 실제 WiperState가 바뀌지 않으면 완료되지 않는 것이 맞다. 상태 유실 후에는 처음부터 연습.
7. 복습 동의 후 시작/완료 이력, 재실행 복원, 삭제·동의 철회 후 삭제 확인.
8. 차량 상태에서 각 문을 바꾸고 재조회. 잠김+열림은 두 신호를 표시. 벨트/워셔 경고는 에뮬레이터 지원 여부에 따라 미확인일 수 있다.
9. 기본 내비게이션에서 목적지/즐겨찾기 설정 → 앱 경로 준비에서 정보/즐겨찾기 조회 → 옵션 변경 또는 즐겨찾기 요청. 성공 콜백·오류·무응답을 각각 확인. 무응답은 내비게이션 화면을 직접 확인 후 재연결.

## 아직 해결하지 않은 항목

- Pleos 기본 내비게이션의 상세 지도 누락 및 Virtual Console의 P 전환 실패는 이번 기능 추가와 별개다. 해결했다고 주장하지 않는다.
- 도로 폭/차로 수 기반 경로 비교, 지도 임베딩, 차량별 공식 매뉴얼 전체 콘텐츠, 모든 경고등 자동 구독, 공조/김서림 실습, 실제 주행 음성 코칭, ADAS·후측방 경보, 다중 사용자 계정은 미구현이다.
- Windows·Pleos의 런타임과 서비스 권한을 클라우드 빌드만으로 보장할 수 없다. 지원하지 않는 서비스를 우회하거나 성공값을 가짜로 만들지 않는다.

## 2026-11-07: 파일 선택기 없이 내부 설정 백업

Windows 화면 검증에서 파일 저장 버튼을 두 번 눌렀으나 파일 선택기가 보이지 않고 취소 결과가 돌아왔다. DocumentsUI 미제공 또는 정책 등 정확한 원인은 확인되지 않았다. 파일 백업 성공으로 기록하지 않는다.

설정에 **현재 설정 내부 백업 / 내부 백업 복원**을 추가했다. 앱 전용 저장소 한 곳에 설정과 시각을 보관하며 파일 선택기를 호출하지 않는다. 기존 백업 교체와 복원은 각각 확인 후 진행한다. 복원 내용을 보는 것만으로 현재 설정이 바뀌지 않는다. 복습 기록 저장소는 접근/수정하지 않는다. 내부 백업은 앱 삭제·데이터 초기화 때 사라지며 클라우드 백업/기기 이전에서 제외한다. 외부 파일 백업 기능은 별도로 남겨 두었다.

확인 순서: 현재 설정 내부 백업 → 크기/테마 변경 → 내부 백업 복원 화면 열기 → 취소 시 변경값 유지 → 다시 열고 복원 적용 → 원래 값 확인 → 앱 재실행 후 유지 확인. 기존 복습 기록도 전후 비교한다. 새 저장소의 지속성/미확정 조회/교체/복습 보존 계측 테스트를 추가했으며 클라우드에서는 컴파일만 수행한다.
